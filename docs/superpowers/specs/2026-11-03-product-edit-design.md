# 상품 편집 화면 설계

## 의도

상품 상세에서 편집으로 이동했을 때 기존 상품 데이터를 새 업로드 화면의 입력 폼에 채워 보여주고, 동일한 편집 경험을 제공한다.

## 목표와 범위

- 상세 화면의 React Query 캐시 `['product', productId]`를 편집 폼의 초기 데이터로 사용한다.
- 캐시가 없으면 편집 페이지에서 상품 API를 호출해 데이터를 가져온다.
- 제목, 설명, 해시태그, 유료 설정을 기존 값으로 채우고 현재 이미지를 미리보기로 표시한다.
- 이미지를 바꾸지 않은 저장은 이미지 재업로드 없이 상품 정보만 갱신한다. 새 이미지를 선택한 경우 업로드 후 상품 이미지 키를 갱신한다.
- 저장 API에서 로그인과 상품 소유권을 확인한다.

## 비목표

- 게시판 편집을 이 변경에 포함하지 않는다.
- 다운로드 권한이나 상품 판매 정책을 변경하지 않는다.
- 이미지 크기 선택 UI를 추가하지 않는다.

## 접근 방식

- `/upload?mode=edit&id=...`에서 create/edit 분기: 경로는 재사용하지만 게시판·신규 등록 흐름과 편집 분기가 한 페이지에 모인다.
- 기존 `/product/[id]/setting` 경로에서 업로드 폼 컴포넌트를 재사용: 현재 수정 진입점을 유지하면서 등록·수정 UI를 일관되게 유지한다. **선택**.
- 편집 화면을 별도 복제: 구현은 독립적이나 폼 UI와 동작의 중복이 생긴다.

## 구현 결정

- 편집 페이지 쿼리는 상세 페이지와 동일한 `['product', productId]` 키를 쓴다.
- 캐시 데이터를 즉시 초기값으로 적용하고, 캐시 미스 시 API 조회를 수행한다.
- 기존 이미지 미리보기와 새로 선택한 업로드 파일을 별도로 관리한다.
- 저장 성공 후 상품 쿼리를 갱신하고 상세 화면으로 돌아간다.

## 남은 구현 선택

- 편집 폼과 등록 폼이 공유할 공통 컴포넌트 경계 및 기존 수정 API 재사용 여부는 코드 구조에 따라 구현자가 정한다.
