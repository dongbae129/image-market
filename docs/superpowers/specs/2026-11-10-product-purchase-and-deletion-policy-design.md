# Product 구매·이미지 버전·삭제 정책 설계

> 범위 갱신: 2026-11-16. 일반적인 Product 수정·판매 중단 흐름과 Pro 버전 구매·재다운로드를 완료하고 사용자 확인까지 마쳤다. 권리·안전 신고와 강제 차단은 후속 단계로 미룬다.

## 의도

Product의 이미지가 수정되거나 판매가 중단되어도 구매자가 무엇을 구매했는지 명확하고, 구매 당시 받은 Pro 원본을 다시 다운로드할 수 있도록 정책을 정한다. 이 문서는 Product만 다루며 User 탈퇴와 Board 삭제 정책은 범위에 포함하지 않는다. 기존 삭제 구현은 새 정책의 기준으로 삼지 않는다.

## 목표와 범위

- `auth=false`는 무료 상품으로 취급하고 736px 이미지를 제공한다.
- `auth=true`는 Pro 상품으로 취급하고, 재화를 사용해 구매한 버전의 원본을 제공한다.
- Pro 사용권은 상품 버전 단위로 발급한다. 구매자는 구매한 버전을 추가 재화 차감 없이 재다운로드할 수 있다.
- 당장은 판매자가 가격을 정하지 않는다. 구매자는 코인 10개 또는 보너스 쿠폰 1장으로 Pro 버전을 구매하고, 결제 수단과 차감량을 기록한다.
- 판매자가 이미지를 바꾸더라도 `Product.id`와 상품 페이지의 정체성을 유지한다.
- 일반 상품 삭제는 신규 노출과 구매를 중단하되, 기존 구매자의 구매 버전 권한을 보존한다.
- 일반 삭제 이후에도 기존 구매자는 만료 없이 해당 버전을 재다운로드할 수 있다.
- 결제, 권한 발급, 다운로드 제공이 서로 불일치하지 않도록 구매 기록을 남긴다.
- 구매한 Pro 버전은 삭제 후에도 찾고 다시 받을 수 있도록 회원별 구매 내역을 제공한다.

## 현재 구현 및 확인 상태

- Product 이미지 처리 SQS 메시지는 현재 리사이저가 요구하는 `feenId`, `tempKeys`, `tableType` 형식으로 전송한다. Product 생성과 이미지 교체 처리가 정상 동작함을 사용자가 확인했다. Lambda 코드는 변경하지 않았다.
- 판매 중단은 `saleStatus = WITHDRAWN`으로 처리한다. 공개 상세·목록·판매자 상품 조회에서 제외하고 신규 Pro 구매를 막는다.
- 사용자가 판매 중단 후에도 기존 구매자가 구매한 Pro 버전을 구매내역에서 다시 다운로드할 수 있음을 확인했다.
- Product의 현재 Pro 버전 번호는 `ProductVersion` 중 `ACTIVE`인 행을 조회해 파악한다. 상세 API는 최신 활성 버전을 반환하지만 현재 상품 화면에는 버전 번호를 표시하지 않는다. 구매내역은 구매한 버전 번호를 표시한다.
- 이번 확인은 실제 앱에서 수행했다. 테스트 코드는 추가하거나 실행하지 않았다.

## 비목표

- Board 삭제와 User 탈퇴 정책을 정하지 않는다.
- 판매자 직접 가격 설정과 판매자 정산은 이번 범위에서 제외한다. 이후 가격 기능을 추가할 수 있도록 구매 기록에 실제 사용한 화폐 종류와 차감량을 남긴다.
- 저작권·안전 신고 접수, 운영자 검토, 강제 차단, 환불은 이번 단계에서 구현하지 않는다. 관련 정책과 동작은 후속 단계에서 정한다.
- Board 삭제와 User 탈퇴 정책은 이번 Product 범위에서 다루지 않는다.

## 접근 방식

- 이미지 교체 때마다 새 `Product` 행과 새 ID를 만든다. 구매자별 과거 버전을 보존하기 쉽지만, 상품 페이지와 댓글·좋아요·공유 링크가 여러 ID로 갈라질 수 있어 선택하지 않는다.
- `Product`는 안정적인 상품 페이지로 유지하고, 구매 대상인 Pro 원본을 `ProductVersion`으로 분리한다. 구매 권한이 특정 버전을 가리켜 구매 당시 파일을 보존할 수 있으므로 **선택**.
- 모든 이미지 교체를 현재 Product 행에 덮어쓴다. 단순하지만 Pro 구매자가 재다운로드할 때 받은 이미지가 바뀔 수 있으므로 Pro에는 선택하지 않는다.

## 정책 결정

### 무료 상품

- 무료 버전은 736px 이미지 다운로드를 제공한다.
- 상품 작성자만 상품을 수정하거나 판매 중단할 수 있다. 화면에서 관리 메뉴를 작성자에게만 표시하고, API에서도 작성자 소유권을 다시 확인한다.
- 이미지 교체는 기존 `Product`를 업데이트하고 `Product.id`를 유지한다. 구매 사용권 보존 목적의 이미지 버전 기록은 만들지 않는다.
- 파일은 CDN 캐시 충돌을 피하도록 새 저장 키를 사용하고, Product가 새 키를 가리키게 한다. 더 이상 참조하지 않는 파일의 정리는 별도 저장소 정책에 따른다.

### Pro 상품과 버전

- Pro 상품은 재화 결제 대상인 이미지 버전의 원본을 제공한다.
- Pro 원본 이미지가 교체되면 기존 버전을 덮어쓰지 않고 같은 Product에 새 `ProductVersion`을 추가한다. 상품 페이지는 계속 같은 `Product.id`를 사용한다.
- 구매 기록은 `Product.id`만이 아니라 구매한 `ProductVersion.id`를 가리킨다.
- 버전 번호는 `ProductVersion.version`에 저장한다. 사용권 행은 `productVersionId` 외에 번호를 중복 저장하지 않으며, 해당 버전 행과 조인해 번호를 확인한다.
- 한 버전에 대한 최초 구매 때 재화를 차감하고 사용권을 발급한다. 동일 버전 재다운로드는 추가 차감하지 않는다. 새 이미지 버전은 새 구매 대상이다.
- 현재 Pro 버전은 코인 10개 또는 보너스 쿠폰 1장 중 하나를 선택해 구매한다. 선택된 수단의 잔액만 차감하고 구매 기록에 수단과 차감량을 저장한다.
- 구매 당시 버전 파일과 권한 기록은 기존 구매자가 재다운로드할 수 있도록 보존한다.
- 사용권은 만료되지 않는다. 일반 삭제 뒤에도 구매한 버전의 재다운로드를 계속 제공한다.

### 무료/Pro 전환

- 무료에서 Pro로 바뀌면 판매할 원본을 새 Pro 버전으로 등록한다. Pro에서 무료로 바뀌면 현재 Pro 버전의 신규 판매를 종료하고 상품을 무료 상태로 전환한다.
- 접근 유형 전환 이력은 기록한다. 과거 Pro 버전의 구매 권한은 무료 전환으로 취소하지 않는다.
- 무료 버전 다운로드에는 Pro 사용권을 발급하지 않는다.

### 일반 삭제

- 일반 삭제 요청 시 상품을 즉시 공개 목록과 검색에서 내리고 신규 구매를 막는다.
- 기존 구매자는 이미 구매한 Pro 버전을 계속 다운로드할 수 있다. 구매 기록과 버전 파일을 보존한다.
- 일반 삭제는 DB 행과 이미지 파일의 물리 삭제가 아니라 공개 판매 중단으로 처리한다.
- 판매 중단 후에는 직접 API 요청을 포함해 상품을 수정할 수 없다. 복구·재게시 기능이 없으므로 현재는 최종 상태로 취급한다.

### 후속 단계: 권리·안전 처리

- 신고 접수, 운영자 권한과 검토 UI, Product/버전 강제 차단, 기존 구매자 다운로드 차단, 환불 기준을 별도로 설계한다.
- 스키마와 다운로드 코드에 남아 있는 `TAKEN_DOWN` 상태 및 방어 코드는 향후 처리를 위한 기반이다. 현재 운영자가 이를 실행하는 API/UI가 없으므로 강제 차단 기능은 완료된 것으로 보지 않는다.

### 구매 일관성

- 재화 차감과 해당 버전 사용권 발급은 원자적으로 처리한다.
- 동일 요청 재시도에 중복 과금이나 중복 사용권 생성이 생기지 않도록 구매 요청에 멱등성을 적용한다.
- 다운로드 링크 발급 실패 시 구매자의 재화만 차감된 채 권한이 누락되지 않도록 한다. 구체적인 실패 복구 동작은 구현 계획에서 정한다.

## 데이터 설계 방향

- `Product.auth`는 해당 상품이 Pro인지 나타낸다. `ProductEntitlement`는 어떤 회원이 어떤 `ProductVersion`을 구매했는지 기록한다. 두 값은 역할이 다르다.
- `Product`: 작성자와 상품 페이지 정보, 현재 공개 상태와 접근 유형, 무료 이미지의 현재 저장 키. 현재 Pro 버전 참조 필드를 별도로 두지 않고, `ProductVersion`에서 해당 Product의 `ACTIVE` 버전을 조회한다.
- `ProductVersion`: 구매 대상인 Pro 이미지의 기본 저장 키, 버전 생성 시점과 판매 상태. 파생 파일은 `474x/`, `736x/`, `original/` prefix 아래 기본 키로 구분한다.
- 구매/사용권 기록: 회원, ProductVersion, 결제 수단(코인 또는 보너스 쿠폰), 차감량, 생성 시점 및 멱등 키를 기록.
- Prisma의 기존 `ProductAuth` 테이블은 `Product.auth` 필드나 새 `ProductEntitlement` 모델과 별개이며 현재 구매 흐름에서는 사용하지 않는다.
- 구매 내역의 상품명은 구매 시점 제목으로 고정한다. 구매 순간의 제목을 사용권 기록에 저장한다.
- 일반 판매 중단은 상품 공개 상태 변경으로 표현하고, 구매 버전 데이터와 종속 삭제하지 않는다.

현재 버전 조회는 일반 쓰기 경로에서 이전 `ACTIVE` 버전을 `RETIRED`로 바꾸고 새 버전을 `ACTIVE`로 만드는 규칙에 따른다. DB에는 Product별 `ACTIVE` 버전을 하나로 제한하는 고유 제약이 없으므로 상세 API는 최신 `ACTIVE` 버전을 선택한다.

## 남은 구현 선택

- 향후 상품 복구·재게시 지원 여부와 방식.
- 신고 접수·운영자 권한·강제 차단 흐름과 차단된 구매의 환불 운영 절차.
- 무료 파일 교체 뒤 참조되지 않는 S3 객체와 CDN 캐시를 정리하는 시점.
- 추후 판매자 직접 가격 설정 UI와 단가 정책.
